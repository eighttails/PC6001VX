== Introduction
image::doc/overview.png[]

This program is a port of PC6001V, a PC-6001 emulator created by http://papicom.net[Yumitaro], modified to run on Linux and other platforms. +
The X at the end of PC6001VX stands for cross-platform. +
The targets are UNIX-like OSes such as Linux and Android. As a portability check we also release Windows binaries. +

== Getting Started
=== Requirements
* ROM files +
In principle, the emulator requires ROM files dumped from a real PC-6001 series machine. See http://p6ers.net/hashi/suidashi.html[here] for instructions on how to dump them from real hardware. +
If you do not own a real machine, another option is to use the compatible ROM created by http://000.la.coocan.jp/p6/basic.html[Akikawa]. The compatible ROM is embedded in the emulator binary and can be enabled in the settings. +
When using the compatible ROM, the behavior corresponds to the original PC-6001, PC-6001A, PC-6001mk2 or PC-6601. PC-6001mk2SR and PC-6601SR can also be selected, but BASIC mode 6 is not supported. Choose them when you want to speed up software that only uses modes up to 5 by turning bus requests off. +
The required ROM files are listed below. +
[WARNING]
On platforms other than Windows, the emulator will fail to start if the letter case of the file names is wrong. Please be careful.

* WAV files +
On mk2 and later models, the fixed words of the speech synthesizer must be provided as WAV files. +
Run `talk"f41."` on a real machine in mode 5 or 6 and record the audio under the name f41.wav. +
Prepare f42~f44.wav in the same way. +
As for the WAV format, the author has verified operation with 44kHz mono WAV files. +
Without the WAV files, the fixed words will not be played. +

=== First-time Setup
Once the required files are ready, start PC6001VX. For how to launch it, refer to the platform specific information matching your OS. +
On the first start you should see the following error. +

image::doc/firstboot.png[]

The emulator looks for the ROM files inside the folder shown here, so copy the ROM files to that location, or, if your ROM files are already stored somewhere else, you can change the setting to point there. To change the setting, click "Yes" and specify the folder where the ROM files are located. +

If you click "No" here, the following dialog is shown. +

image::doc/compatiblerom.png[]

Choosing "Yes" here starts the emulator with the compatible ROM built into the binary. Use this if you do not have ROMs dumped from real hardware. +
By default the emulator behaves like a PC-6001, but you can also select a PC-6601 equivalent ROM in the settings dialog.

If the CRC of the specified ROM file does not match the commonly known one, the following message is displayed. +

image::doc/romcrc.png[]

You will be warned, but clicking "Yes" makes the emulator start from then on without checking the ROM CRC. +
From that point on, however, everything is at your own risk. +

=== Platform Specific Information
==== Windows
* How to start +
Simply double-click PC6001VX.exe.

Build from source and run it. See the developer information chapter for how to build. +

==== Android
* How to start +
Tap the PC6001VX icon registered in the application menu. +

On Android the location of the configuration files depends on the device and cannot be stated in general, but it is usually created in a place normal file managers cannot access. Check the exact location in the preferences dialog. +
* Sharing files +
On Android files cannot be written directly outside of the app sandbox. When you take a snapshot or export a TAPE(SAVE) image, a share menu is shown and you can send the file to any app such as a file manager or an image editor. +

** Replay +
The replay menu changes depending on the current state. +
*** [Normal] +
**** Playback +
**** Record +
**** Resume recording +
If a resume file was left when a previously recorded replay ended, "Resume recording" lets you continue recording that replay from where recording stopped.
**** Convert replay to movie +
Converts a saved replay file to a movie. +
First select the replay file to convert, then specify where to save the movie. +
Then playback of the replay and encoding of the movie start together. When the replay ends, the movie encoding finishes automatically.


*** [Playing] +
**** Stop playback +
Stops replay playback.

*** [Recording] +
**** Stop Recording +
Stops recording. +
When stopping, a "(replay file name).resume" file is left, just like with a checkpoint. +

**** Checkpoint +
While recording a replay, you can save the current point in the recording. +
A "(replay file name).resume" file is left in the same folder as the replay file (.ddr). +

**** Back to checkpoint +
If you fail while recording a game replay, you can return to the last "checkpoint" without stopping the replay recording and try again. +

**** Back to previous checkpoint +
If you fail while recording a game replay, sometimes even rewinding with "Back to checkpoint" leaves you stuck at the checkpoint. Up to 5 checkpoints of history are kept, so you can redo from the previous checkpoint. +
If you use this, the most recent checkpoint is lost. +

** Video capture +
Records the emulator's operation as a movie file. +
To stop recording, select this menu again (it changes to "Stop video capture"). +
The movie is recorded in WebM format. (MP4 support has been skipped due to licensing risks.) It is not a widely used format, but YouTube supports it officially. +
During recording the emulation speed drops drastically (about 1/10 on the author's machine), so it is currently impossible to play a game while recording. +
The intended workflow is to record your play as a replay first, then play back the replay while recording a movie. (If the replay ends during recording, the movie recording ends at that point.) +
Regardless of the machine's speed, the resulting movie is 60FPS. +

** 4:3 TV display +
Generally the aspect ratio of PC pixels is 1:1. +
On a TV, however, it is 1.16:1, i.e. a bit taller. +
So displaying it as-is on a PC results in a stretched-wide image. +
4:3 display shrinks the horizontal direction by a factor of 1.16 to compensate. +

** Scanline +
The horizontal frequency of the P6 is 15kHz, the same as a TV. +
TVs use an interlace scheme where scan lines are split into even and odd fields and displayed alternately. +
However, most computers including the P6 use a non-interlace scheme where even and odd scan lines scan the same position, in order to reduce flicker. +
In this case the number of scan lines is halved, leaving gaps between the scan lines. +
Scanline mode reproduces these gaps. +
To achieve scanline mode in an emulator you need twice the screen resolution of the real machine (640x400 or more where the real machine is 320x200). +
Naturally the display becomes heavier and processing speed drops. +

** Filtering +
Applies filtering when the graphics are magnified or shown in 4:3. It is on by default. +
This is meant to make non-integer magnifications look natural, but if you dislike the blurry look, you can get a crisp pixel display by following the steps below. +

. Turn filtering off. +
. Turn 4:3 display off. +
. Set the display size to an integer multiple. +

** Tilt mode +
+
image::doc/tilt.png[]
A joke feature inspired by the 3DS version of Space Harrier. +
The screen tilts in response to the joystick or the left/right cursor keys. (; +
In fullscreen mode, or when the status bar is hidden, a display frame is shown. The original machine shows a PC-6042, others show a PC-60m43. +

** Mode4 color +
Selects the color bleeding of screen mode 4 in BASIC modes 1-4. +

** Frameskip +
Specifies the emulator's frameskip interval. +

** Romaji input +
Toggles Romaji input on/off in KANA mode. +

** Turbo tape +
Runs without wait states while reading TAPE. +
It is only unthrottled while the relay is ON and returns to normal speed as soon as the relay turns OFF. +
Since it simply runs at full speed, timing is less likely to change and it is reliable, but on slow machines it may not produce a sufficient effect. +

** Boost up +
The TAPE transfer rate is 1200 baud, which seems to be determined by the reliability of the TAPE medium and the processing power of the sub CPU. +
The main CPU (Z80) apparently has headroom and there is quite a lot of waiting. +
By monitoring the BASIC work area and sending the next data as soon as the machine starts waiting, wasted wait time is reduced and loading becomes efficient. +
In the author's tests, roughly 9x on N60 and 5x on N60m were achieved. +
The limit differing by BASIC mode is presumably due to differences in internal processing. +
The maximum factor can be changed under [Settings]-[Preferences]-[Other]. +
While it reliably speeds things up, timing-sensitive software may drop data, and custom loaders that do not use ROM routines may not work with it at all. +
It is not a cure-all, so use it selectively. +

If you use a mouse with a wheel, you can change the emulation speed. +
Wheel up speeds up, wheel down slows down, and clicking the middle button returns to normal speed. +
The speed changes in steps of 10% up to 2x, and in steps of 100% above 2x. +

Build on the MSYS2 environment. +

. Download and install MSYS2 from https://github.com/msys2/msys2-installer/releases/[here]. +
VC++ is not supported. +
MSYS2 packages update quickly and upgrades very often cause regressions, so it is recommended not to update packages (`pacman -Sy`) and to keep the versions fixed. The author has verified building and running with the environment built from the following installer (64-bit). +
https://github.com/msys2/msys2-installer/releases/download/2026-03-22/msys2-base-x86_64-20260322.sfx.exe
. Run ucrt64.exe in the folder where MSYS2 was installed. +
. Extract the downloaded PC6001VX sources into the home folder on MSYS. +
. Run `cd PC6001VX/win32` to move the current directory to the win32 folder of the source folder. +
. Run `bash ./release.sh`. It installs the required tools (QtCreator, SDL2, asciidoctor), builds the static Qt/FFmpeg, does a Release build with CMake and creates the distribution folder, all in one go. +
The static Qt is placed at `/ucrt64/local/qt6-static-private`. +
. `release.sh` internally uses `buildrelease.sh` to Release-build the root `CMakeLists.txt` with Ninja + CMake. The distribution EXE is output to `PC6001VX_release/PC6001VX_(version)_win_64bit`. +
. If you modify and debug the sources yourself, open the root CMakeLists.txt in QtCreator and build with a kit using MSYS2 UCRT64 + the static Qt. How to configure the kit is out of scope of this manual. +
